## P1 — Critical (must fix before CloudPayments submission)

### L1 — Landing: `LIVE · 04.20.2026` дата статичная
Sсегодня 30 мая 2026. Клиент видит «не обновлялось 6 недель».
Fix: динамически генерить дату из `new Date()`.

### L2 — Landing «Сканируем вакансии из» список лжёт
Сейчас перечислены: hh.ru, LinkedIn, Habr Career, Telegram Jobs, getmatch, Tinkoff, Sber AI, Yandex, Ozon Tech, Wildberries, Alfa-Bank, VK.
Реально работает только hh.ru. TG worker не задеплоен. LinkedIn/Habr — никогда не было.
**CloudPayments-модератор может расценить как введение в заблуждение.**
Fix: оставить только hh.ru + честную приписку «в ближайшее время — Telegram».

### L3 — Landing hero radar показывает «tg channels · 28»
Та же проблема — обещаем TG, которого нет.
Fix: заменить на «AI matching» или убрать строку.

### Pi1 — /pipeline empty state обещает «отправит через HH»
Inconsistency с моим landing-fix. CloudPayments прочитает empty state.
Fix: переписать на «AI сгенерирует cover-letter и подготовит к отправке».

### H1 — /connect-hh обещает «отправлял отклики от вашего имени»
Прямо нарушает то, что я скрыл с лендинга.
Fix: переписать на «безопасное подключение для сканирования вакансий».

### H2 — /connect-hh disclaimer «использование автоматизации нарушает ToS hh.ru»
**Самое острое: модератор увидит этот текст и автоматически откажет** (нарушение прав третьих лиц).
Fix: убрать или переформулировать в нейтральное «hh.ru может ограничить access к API — мы используем его в рамках их условий».

### Au1 — Logged-in user → /signup?intent=pro теряет intent
Middleware молча редиректит на /dashboard, intent params в URL присутствуют но не используются.
Fix: middleware распознать intent=pro|premium и перенаправить на checkout (если onboarding done) или /onboarding с сохранением intent.
